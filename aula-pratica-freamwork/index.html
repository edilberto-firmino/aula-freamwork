PASSO 01

O que vamos construir

Na aula anterior, o JavaScript procurava elementos no HTML e alterava a lista manualmente. Nesta aula, vamos reconstruir o cadastro de alunos com React. A interface terá formulário, lista, contador, filtro e mensagens de carregamento, sucesso e erro.

O contrato continua o mesmo: nome, email e curso. O backend valida e grava em SQLite. O frontend não abre o arquivo do banco.

Objetivo da aula: explicar e demonstrar o caminho de um cadastro, do evento no React até a gravação no SQLite e sua exibição na tela. Use somente dados fictícios.

Escopo principal: criar e consultar registros. Login, edição, exclusão e publicação ficam fora desta prática. React é uma biblioteca de interfaces; Vite é a ferramenta que prepara e serve o frontend durante o desenvolvimento.

Ao final, você conseguirá

  • Separar a interface em componentes e transmitir dados por props.
  • Controlar campos, lista e mensagens com useState.
  • Carregar dados com useEffect e enviar JSON com fetch.
  • Identificar se uma falha está no React, no HTTP ou no SQLite.

Componente é uma função que retorna a interface. JSX é a sintaxe de marcação dentro do JavaScript. Props são dados recebidos do componente pai. Estado é a memória que influencia a renderização.

Use className no lugar de class e htmlFor no lugar de for. Expressões JavaScript ficam entre chaves. Nomes de componentes começam com maiúscula.

Não modifique arrays de estado com push. Crie um novo array e chame o setter. Atualizar o estado solicita uma nova renderização; não altera imediatamente a variável da função em execução.

PASSO 07

Preparar o backend e o SQLite

Vamos preservar o percurso Python/Flask da aula anterior. Crie os dois arquivos abaixo dentro de backend. O backend prepara a tabela quando criar_app() é chamado.

backend/requirements.txtBaixar arquivo
Flask==3.1.2
backend/app.pyBaixar arquivo
from contextlib import closing
from pathlib import Path
import re
import sqlite3

from flask import Flask, jsonify, request

BASE = Path(__file__).resolve().parent


def criar_app(caminho_banco=None):
    app = Flask(__name__)
    app.config['MAX_CONTENT_LENGTH'] = 16 * 1024
    caminho = Path(caminho_banco) if caminho_banco else BASE / 'cadastros.db'

    def conectar():
        banco = sqlite3.connect(caminho)
        banco.row_factory = sqlite3.Row
        return banco

    with closing(conectar()) as banco, banco:
        banco.execute('''CREATE TABLE IF NOT EXISTS alunos (
            id INTEGER PRIMARY KEY,
            nome TEXT NOT NULL CHECK(length(trim(nome)) BETWEEN 2 AND 80),
            email TEXT NOT NULL UNIQUE COLLATE NOCASE,
            curso TEXT NOT NULL CHECK(length(trim(curso)) BETWEEN 2 AND 80)
        )''')

    @app.get('/api/alunos')
    def listar():
        with closing(conectar()) as banco:
            linhas = banco.execute(
                'SELECT id, nome, email, curso FROM alunos ORDER BY id DESC'
            ).fetchall()
        return jsonify([dict(linha) for linha in linhas])

    @app.post('/api/alunos')
    def cadastrar():
        dados = request.get_json(silent=True)
        if not isinstance(dados, dict):
            return jsonify(erro='Envie um objeto JSON válido.'), 400
        campos = ('nome', 'email', 'curso')
        if any(not isinstance(dados.get(campo), str) for campo in campos):
            return jsonify(erro='Nome, e-mail e curso devem ser textos.'), 400
        nome, email, curso = (dados[campo].strip() for campo in campos)
        email = email.lower()
        if not (2 <= len(nome) <= 80 and 2 <= len(curso) <= 80):
            return jsonify(erro='Nome e curso precisam ter de 2 a 80 caracteres.'), 400
        if len(email) > 120 or not re.fullmatch(r'[^\s@]+@[^\s@]+\.[^\s@]+', email):
            return jsonify(erro='Informe um e-mail válido com até 120 caracteres.'), 400
        try:
            with closing(conectar()) as banco, banco:
                cursor = banco.execute(
                    'INSERT INTO alunos (nome, email, curso) VALUES (?, ?, ?)',
                    (nome, email, curso),
                )
                aluno_id = cursor.lastrowid
        except sqlite3.IntegrityError as erro:
            if erro.sqlite_errorname == 'SQLITE_CONSTRAINT_UNIQUE':
                return jsonify(erro='Este e-mail já está cadastrado.'), 409
            raise
        return jsonify(id=aluno_id, nome=nome, email=email, curso=curso), 201

    @app.errorhandler(413)
    def muito_grande(erro):
        return jsonify(erro='O corpo da requisição excedeu o limite.'), 413

    return app


if __name__ == '__main__':
    criar_app().run(host='127.0.0.1', port=3000, debug=False)

Leia antes de executar

  • criar_app organiza a inicialização e permite testar com um banco temporário.
  • Path(__file__) mantém o banco ao lado de app.py, independentemente da pasta do terminal.
  • with banco confirma a transação no sucesso e reverte em caso de erro; closing fecha a conexão.
  • Os ? recebem valores separados do SQL. Nunca monte SQL concatenando os campos.
  • O e-mail é normalizado e tem restrição UNIQUE. A validação do servidor continua obrigatória.

Para reaproveitar dados da aula anterior, pare o backend antigo, faça uma cópia de segurança e copie o cadastros.db para backend. A tabela precisa ter o mesmo esquema. Não mova o banco para frontend. Sem essa cópia, esta aula inicia um banco novo.

frontend/src/api.jsBaixar arquivo
export async function requisitar(caminho, opcoes = {}) {
  const resposta = await fetch(caminho, opcoes);
  const dados = await resposta.json().catch(() => {
    throw new Error('Resposta inesperada. Confira o backend e o proxy do Vite.');
  });
  if (!resposta.ok) throw new Error(dados.erro || 'Não foi possível concluir a operação.');
  return dados;
}

export function listarAlunos(signal) {
  return requisitar('/api/alunos', { signal });
}

export function cadastrarAluno(dados) {
  return requisitar('/api/alunos', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(dados),
  });
}

O módulo centraliza o acesso HTTP. fetch não lança erro automaticamente para status 400 ou 409: por isso verificamos resposta.ok. JSON.stringify transforma o objeto em texto para envio.

signal permite cancelar consultas antigas com AbortController. O caminho relativo /api/alunos passa pelo proxy; não o substitua pela porta 3000 no frontend sem tratar CORS.

PASSO 11

Componente do formulário

Crie FormularioAluno.jsx. Cada campo tem value vindo do estado e onChange para atualizá-lo. Esse é um formulário controlado.

frontend/src/components/FormularioAluno.jsxBaixar arquivo
import { useRef, useState } from 'react';
import { cadastrarAluno } from '../api.js';

const vazio = { nome: '', email: '', curso: '' };

export default function FormularioAluno({ aoCadastrar }) {
  const [campos, setCampos] = useState(vazio);
  const [salvando, setSalvando] = useState(false);
  const [mensagem, setMensagem] = useState('');
  const [erro, setErro] = useState(false);
  const enviando = useRef(false);

  function alterar(evento) {
    const { name, value } = evento.target;
    setCampos(anteriores => ({ ...anteriores, [name]: value }));
  }

  async function enviar(evento) {
    evento.preventDefault();
    if (enviando.current) return;
    enviando.current = true;
    setSalvando(true);
    setErro(false);
    setMensagem('Salvando…');
    try {
      const aluno = await cadastrarAluno(campos);
      aoCadastrar(aluno);
      setCampos(vazio);
      setMensagem('Aluno cadastrado com sucesso!');
    } catch (falha) {
      setErro(true);
      setMensagem(falha.message || 'Confira se o servidor está ligado.');
    } finally {
      enviando.current = false;
      setSalvando(false);
    }
  }

  return (
    <section aria-labelledby="titulo-form">
      <p className="etiqueta">01 / CADASTRAR</p>
      <h2 id="titulo-form">Novo aluno</h2>
      <form onSubmit={enviar}>
        <fieldset disabled={salvando}>
          <legend className="sr-only">Dados do aluno</legend>
          <label htmlFor="nome">Nome</label>
          <input id="nome" name="nome" value={campos.nome} onChange={alterar}
            required minLength={2} maxLength={80} autoComplete="name" />
          <label htmlFor="email">E-mail</label>
          <input id="email" name="email" type="email" value={campos.email} onChange={alterar}
            required maxLength={120} autoComplete="email" />
          <label htmlFor="curso">Curso</label>
          <input id="curso" name="curso" value={campos.curso} onChange={alterar}
            required minLength={2} maxLength={80} />
          <button type="submit">{salvando ? 'Salvando…' : 'Cadastrar aluno'}</button>
        </fieldset>
      </form>
      <p role="status" aria-live="polite" className={erro ? 'mensagem erro' : 'mensagem'}>
        {mensagem}
      </p>
    </section>
  );
}

Entenda o fluxo

  1. O usuário digita; alterar cria uma cópia de campos com o valor novo.
  2. O submit chama enviar; preventDefault evita a navegação padrão.
  3. O botão e os campos ficam desabilitados durante o envio.
  4. A API valida e responde com o aluno salvo, incluindo o id.
  5. A prop aoCadastrar avisa o componente pai; o formulário limpa o estado.
  6. Um erro mantém os valores digitados e exibe uma mensagem.

useRef mantém uma trava imediata entre renderizações, sem renderizar a tela ao mudar. useState continua responsável pela aparência do botão. Os hooks ficam no topo do componente, nunca dentro de condições ou loops.

required e os limites ajudam o usuário; requisições diretas podem ignorá-los. Por isso o backend faz as mesmas verificações.

export default function ListaAlunos({ alunos, carregando, erro, atualizar, filtro, aoFiltrar }) {
  const visiveis = alunos.filter(aluno =>
    aluno.nome.toLocaleLowerCase('pt-BR').includes(filtro.toLocaleLowerCase('pt-BR')),
  );

  return (
    <section aria-labelledby="titulo-lista" aria-busy={carregando}>
      <p className="etiqueta">02 / CONSULTAR</p>
      <div className="cabecalho-lista">
        <h2 id="titulo-lista">Alunos <span className="contador">{alunos.length}</span></h2>
        <button type="button" className="secundario" onClick={atualizar} disabled={carregando}>
          {carregando ? 'Carregando…' : 'Atualizar lista'}
        </button>
      </div>
      <label htmlFor="filtro">Filtrar por nome</label>
      <input id="filtro" type="search" value={filtro} onChange={e => aoFiltrar(e.target.value)}
        placeholder="Digite parte do nome" />
      {erro && <p role="alert" className="erro">{erro}</p>}
      {carregando && <p role="status">Consultando o banco…</p>}
      {!carregando && !erro && alunos.length === 0 && <p>Nenhum aluno cadastrado ainda.</p>}
      {alunos.length > 0 && visiveis.length === 0 && <p>Nenhum nome corresponde ao filtro.</p>}
      <ul>
        {visiveis.map(aluno => (
          <li key={aluno.id}>
            <strong>{aluno.nome}</strong>
            <span>{aluno.email}</span>
            <span className="curso">{aluno.curso}</span>
          </li>
        ))}
      </ul>
    </section>
  );
}

A lista recebe dados por props. map descreve um item para cada aluno e key={aluno.id} fornece uma identidade estável. Não use a posição no array como identidade de um registro.

O contador vem de alunos.length. O filtro é calculado com filter durante a renderização: não precisamos guardar outra cópia da lista em estado nem criar um efeito só para filtrar.

O total indica todos os registros carregados; filtrar altera apenas os itens visíveis. Os dados continuam no banco. Um nome como <b>Ana</b> aparece como texto porque React escapa strings interpoladas. Não use dangerouslySetInnerHTML para esses campos.

PASSO 13

Componente principal: juntar as partes

frontend/src/App.jsxBaixar arquivo
import { useEffect, useRef, useState } from 'react';
import { listarAlunos } from './api.js';
import FormularioAluno from './components/FormularioAluno.jsx';
import ListaAlunos from './components/ListaAlunos.jsx';

export default function App() {
  const [alunos, setAlunos] = useState([]);
  const [carregando, setCarregando] = useState(true);
  const [erro, setErro] = useState('');
  const [filtro, setFiltro] = useState('');
  const consulta = useRef(null);

  async function atualizar() {
    consulta.current?.abort();
    const controle = new AbortController();
    consulta.current = controle;
    setCarregando(true);
    setErro('');
    try {
      const lista = await listarAlunos(controle.signal);
      if (!controle.signal.aborted) setAlunos(lista);
    } catch (falha) {
      if (!controle.signal.aborted) setErro(falha.message || 'Confira o backend.');
    } finally {
      if (!controle.signal.aborted) setCarregando(false);
    }
  }

  useEffect(() => {
    atualizar();
    return () => consulta.current?.abort();
  }, []);

  function adicionar(aluno) {
    // Uma consulta antiga não deve apagar o cadastro que acabou de chegar.
    consulta.current?.abort();
    setCarregando(false);
    setErro('');
    setAlunos(anteriores => [aluno, ...anteriores.filter(item => item.id !== aluno.id)]);
    setFiltro('');
  }

  return (
    <main>
      <header>
        <p className="etiqueta">AULA PRÁTICA 5 / REACT + API + SQLITE</p>
        <h1>Da tela ao banco.<br /><span>Agora com React.</span></h1>
        <p>Cadastre alunos, acompanhe a lista e veja seus dados persistirem.</p>
      </header>
      <div className="painel">
        <FormularioAluno aoCadastrar={adicionar} />
        <ListaAlunos alunos={alunos} carregando={carregando} erro={erro}
          atualizar={atualizar} filtro={filtro} aoFiltrar={setFiltro} />
      </div>
      <footer>React cuida da interface. Flask valida. SQLite guarda.</footer>
    </main>
  );
}

App é dono do estado compartilhado. Ele passa a lista para ListaAlunos e a função adicionar para FormularioAluno. Esse fluxo permite que componentes irmãos compartilhem dados por meio do pai.

Por que useEffect?

A consulta inicial sincroniza a tela com um sistema externo: a API. O array vazio indica que o efeito não depende de valores reativos que mudam. A limpeza cancela uma consulta pendente quando o efeito é encerrado.

atualizar usa setters e uma ref estáveis, sem ler estado de uma renderização anterior. Cada consulta cancela a anterior, evitando que uma resposta atrasada substitua uma lista mais recente. Ao cadastrar, cancelamos uma consulta anterior e inserimos o registro retornado pela API no estado.

O POST pertence ao evento do formulário. O efeito inicial faz somente GET. No StrictMode você pode observar uma consulta cancelada seguida de outra: isso é esperado durante o desenvolvimento.

Depois de salvar, a lista é atualizada usando o objeto retornado pelo backend; o botão Atualizar lista faz uma nova consulta completa. Essa atualização local não substitui a persistência: recarregar a página permite verificá-la.

Em um terceiro terminal, faça um teste direto da API:

TERMINAL · PowerShell · uma linha por vez
Invoke-RestMethod http://127.0.0.1:3000/api/alunos
$aluno = @{ nome = "Carla Lima"; email = "carla@example.com"; curso = "Computação" } | ConvertTo-Json
Invoke-RestMethod -Uri http://127.0.0.1:3000/api/alunos -Method Post -ContentType "application/json; charset=utf-8" -Body ([System.Text.Encoding]::UTF8.GetBytes($aluno))

Repetir o envio deve resultar em 409. Isso comprova a restrição de e-mail único. O PowerShell pode mostrar esse status como erro de requisição: é o resultado esperado.
